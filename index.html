Lajstrom

Artifact registry on top of any OCI registry.

pre-release · v0.1.0 due 2026-12-04

One server, many repository formats: apt, rpm, maven, pypi, npm and raw files, and any OCI artifact through the /v2 API. Every artifact is stored as an OCI artifact in the registry you already run: ECR, Harbor, Zot, GHCR, docker distribution. Lajstrom owns no bytes, only the index, and the index can always be rebuilt from the registry.

How it works

  1. The OCI registry is the only storage and the source of truth. Lajstrom never stores artifact bytes itself.
  2. The database is a derived, rebuildable index plus a small control plane (repos, users, tokens, permissions).
  3. Clients keep their native tools. pip, apt-get, dnf, mvn, npm and oras talk to Lajstrom as if it were their native repository. Protocol emulation is server-side; no client plugins.
  4. Docker images pass through to the backend registry untouched, with Lajstrom's RBAC and audit in front.

Formats

Each format on main is run by its quick start and by an end-to-end test with the real clients. What each one does.

  • raw files on main
  • pypi on main
  • apt on main
  • maven on main
  • npm on main
  • rpm on main
  • OCI artifacts on main
  • docker images on main
  • terraform modules after v0.1.0

Install

No release is out yet. Until v0.1.0 (due 2026-12-04), build from source with Go 1.27:

git clone https://github.com/lajstrom/lajstrom.git && cd lajstrom
make build && bin/lajstrom version

From v0.1.0 on, the image, signed with cosign:

docker run --rm ghcr.io/lajstrom/lajstrom:v0.1.0 version

The archives with checksums and signatures, Homebrew, Docker Compose, Kubernetes and Helm are in docs/install.md. Bugs and feature requests go to GitHub Issues; to contribute, read CONTRIBUTING.md.
